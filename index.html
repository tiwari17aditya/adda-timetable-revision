DBMS Core Revision Sheet

ACID Properties

  • Atomicity: All operations copy or none. (Managed by Transaction Manager / Log Recovery).
  • Consistency: Database transitions from one valid state to another.
  • Isolation: Transactions execute concurrently without interference. (Concurrency Control: 2-Phase Locking - 2PL, Timestamp Ordering).
  • Durability: Updates persist after commit (Recovery Manager - Write Ahead Logging / WAL, Checkpointing).

Database Normalization

  • 1NF: Atomic values (no repeating groups).
  • 2NF: In 1NF + No partial dependencies (every non-prime attribute belongs fully to candidate keys).
  • 3NF: In 2NF + No transitive dependencies ($A \rightarrow B, B \rightarrow C$, so $A \rightarrow C$ is transitive).
  • BCNF: In 3NF + For every functional dependency $X \rightarrow Y$, $X$ must be a super key.

SQL & Transactions

Transaction Isolation Levels: Read Uncommitted (Dirty Read), Read Committed (Non-repeatable Read), Repeatable Read (Phantom Read), Serializable.

Operating Systems Revision Panel

Process Management & Scheduling

  • Preemptive Scheduling: Round Robin (Time Quanta context switch overhead), Shortest Remaining Time First (SRTF, optimal but suffers starvation), Priority scheduling.
  • Non-Preemptive: FCFS, Shortest Job First (SJF).
  • Semaphores: Wait(S) { while $S \le 0$; $S$-- } | Signal(S) { $S$++ }. Used for mutual exclusion & synchronization.

Memory Management

  • Paging: Logic address split into Page Number ($p$) and Offset ($d$). Translates via Page Table.
  • Virtual Memory: Demand paging. Page faults handled by OS disk retrieval.
  • Page Replacement Algorithms:
    • FIFO (Belady's Anomaly: anomaly where adding frames increases page faults).
    • LRU (Least Recently Used) - needs hardware support.
    • Optimal algorithm - replaces page not needed for longest period.
